# DevKit

Global agent environment for Claude Code, Codex, Cursor, GitHub Copilot and Antigravity.
One source of rules, agents and hooks, linked into each tool.
Skills and MCP servers are not global: install each one through its own install process, per agent or per project, when it is needed.
Canonical repository: [Artic0din/devkit](https://github.com/Artic0din/devkit).

## Layout

| Path | Purpose |
| --- | --- |
| `AGENTS.MD` | Global hard rules, linked into Claude, Codex, Copilot CLI and Antigravity; Cursor reads a full copy in `config/cursor.rules.mdc`, regenerated by `scripts/cursor-rule` and checked in CI. |
| `.github/instructions/` | GitHub Copilot custom instructions, scoped by `applyTo`. |
| `hooks/` | Repository hook scripts. The tool configs under `config/` currently reference `~/.claude/hooks/`. |
| `agents/` | Subagent definitions per tool format. |
| `config/` | Per-tool settings and hooks that get merged into place. |
| `docs/` | Engineering standards referenced from `AGENTS.MD`. |
| `templates/github/` | Default issue forms, PR templates, triage playbook and triage workflow caller; see `docs/github-intake.md`. |
| `scripts/` | Dependency-light helpers: agent locations, cleanup, settings sync, docs listing, browser tooling. |

## Install

On an activated machine, `~/.codex/AGENTS.md`, `~/.claude/CLAUDE.md`, `~/.gemini/GEMINI.md` and `~/.copilot/copilot-instructions.md` link to this repo's `AGENTS.MD`, and `~/.cursor/rules/metisary.mdc` links to `config/cursor.rules.mdc`.
Do not also link `~/.claude/AGENTS.md`: Claude Code would load the rules twice.
Merge the `config/` hook and permission entries into each tool's live settings by hand (additive only), and link `agents/` into `~/.claude/agents` and `~/.codex/agents`.
Before activating a machine, copy every file those steps touch to `~/Metisary/Enviroment/backups/activation-YYYY-MM-DD-<host>/`.
The optional web UI paste lives in `config/ui-paste.md`.

For headless agent browsing on Apple Silicon Macs, see [Obscura](tools.md#obscura).

## Rules

Rules live once. `AGENTS.MD` holds only rules that apply on every request in every tool.
Path-scoped and on-demand content belongs in project rules and `.github/instructions/`.
Keep `AGENTS.MD` under 200 lines.

Downstream repos use a pointer-style `AGENTS.MD`, with repo-specific rules below it and no copied blocks:

```text
READ ~/Metisary/Enviroment/config/AGENTS.MD BEFORE ANYTHING (skip if missing).
```

## Helpers

### Fleet decisions

On a machine with the fleet manager installed separately, open its board with `open "$HOME/Metisary/Enviroment/manager/fleet/dashboard/Open dashboard.command"` and choose **Decisions**.
Use **Still to do** for work awaiting installation or verification.
When a setup decision changes, mark the old decision **Changed later** and record its replacement, reason, source, and affected machines in the board.
For a skill, include its upstream source and which provider installs it.
For a removal, keep an open item for each affected host or application until its absence has been checked there.
Keep account identifiers, credentials and private machine inventories in their existing local stores.

### Scripts

Before an authorized provider cleanup, verify the requested recovery choice on that host.
For a requested backup, pass the pre-change archive, every active registration file (including enabled plugins and marketplaces), and the installed payload paths relative to the archive root.
Include explicit tar entries for every parent directory beneath the supplied root and preserve their permission bits.
The preflight checks each directory and file in a requested payload subtree, including empty directories.
For example, `scripts/provider-cleanup-check preflight --archive BACKUP.tar.gz --root SOURCE --registration plugins.json --registration marketplaces.json --payload skills` checks the live bytes against the archive without extracting it.
Use `preflight --no-backup` only when that cleanup explicitly authorizes proceeding without a backup.
After cleaning the first host, run `scripts/provider-cleanup-check pilot --startup '["devin","skills","list","--json"]' --catalog '["devin","skills","list","--json"]' --expect RETAINED_SKILL` with that provider's native commands and an expected usable skill.
Run the next host's cleanup only after both checks succeed.
When a deliberate full wipe leaves no skills, reinstall one intended skill on the pilot and demonstrate discovery before continuing.

- `scripts/agent-sweep`: reports agent worktrees, branches, idle `node_modules` and unavailable simulators in the shared worktree folder, `~/Metisary/Projects`, `~/Development`, `/private/tmp` and older agent worktree folders (Cursor, Codex, T3, Conductor, Orca, Emdash). `--apply` removes finished worktrees at any age (clean, and their tip is a merged PR's head or their remote branch was deleted after merging) and every worktree idle for `--days` (default 5), each with its branch, uncommitted and unmerged work included, plus merged branches, scratch entries idle as long, `agent-job` folders whose job ended without cleanup (with the Colima profile and disk they recorded), and unavailable simulators. It keeps locked worktrees, ones a process works in, and ones holding nested repositories, submodules, or ignored files that are not rebuildable folders or junk such as `.DS_Store`, since those could be secrets. Tested by `scripts/test-agent-sweep.py`.
- `scripts/agent-job`: `run [--colima] -- COMMAND` runs one agent job in its own scratch folder, `~/Metisary/Enviroment/scratch/agent-job/<id>/`, and with `--colima` its own Colima profile `agent-job-<id>`, without switching the Docker context. When the command succeeds, fails or is interrupted, it deletes that profile with its data disk, checks nothing is left, and removes the folder. A job killed before cleanup is finished by the nightly sweep once neither the job nor its command still runs; the `default` profile and any profile a job did not record are never touched, and a folder holding a Git checkout is kept. Tested by `scripts/test-agent-job.py`.
- `scripts/agent-bin/xcodebuild`: a shim that gives agent builds without `-derivedDataPath` a DerivedData folder (Swift package clones included) outside Git worktrees: the job folder inside `agent-job run`, else `~/Metisary/Enviroment/scratch/xcode/<worktree>-<hash>/`, which the sweep removes once idle for 5 days. Explicit DerivedData and cloned-package paths outside the current and selected project or workspace worktrees are supported. For paths inside the worktree, the shim reports the scratch path to use for both the build and subsequent commands.
- `scripts/agent-sweep-schedule`: `install` adds a LaunchAgent that runs the sweep daily at 03:30 with `--apply`, writing `~/Library/Logs/agent-sweep/YYYY-MM-DD.tsv` and `latest.tsv` and keeping 14 reports; `status`, `run` and `uninstall` do what they say. Run `agent-sweep` without `--apply` for a report that removes nothing.
- `scripts/t3-settings-sync` copies this Mac's T3 Code settings and keybindings to other fleet Macs over SSH (default `ace rex`). It adds missing ACP Registry providers and syncs their enabled state. Existing provider overrides, sign-ins, project overrides and microphones stay on each Mac. Run it with `--apply` to write changes and keep one `.bak-fleet-sync` per file. `install` loads a LaunchAgent that applies on settings changes and every 15 minutes. `status` shows whether the job is loaded and where it last ran. `uninstall` removes it. Restart T3 Code to pick up desktop-only settings.
- `scripts/agent-locations`: `install` puts every agent's worktrees in `~/Metisary/Enviroment/worktrees/<tool>/` and temp files in `~/Metisary/Enviroment/scratch/<tool>/`. Claude Code gets `CLAUDE_CODE_TMPDIR`, the `hooks/claude-worktree.py` WorktreeCreate and WorktreeRemove hooks (removal keeps a worktree with uncommitted, untracked or possibly secret ignored files), and a `hooks/claude-session-env.sh` SessionStart hook that puts `scripts/agent-bin` first on its commands' `PATH`; Cursor's and Codex's worktree folders and T3's scratch folder, which have no setting, become links into the shared folders. `status` reports drift. Scratch idle for 5 days is swept even if a long-idle Claude session still owns it. Tested by `scripts/test-agent-locations` and `hooks/test-claude-worktree.py`.
- `scripts/docs-list.ts`: walks `docs/`, enforces `summary` and `read_when` front matter, prints onboarding summaries.
- `scripts/browser-tools.ts`: standalone Chrome DevTools helper (`start --profile`, `nav`, `eval`, `screenshot`, `console`, `network`, `search --content`, `content`, `inspect`, `kill --all --force`); build a binary with `bun build scripts/browser-tools.ts --compile --target bun --outfile bin/browser-tools`.

- [Fleet verification](docs/fleet-verification.md) compares active native and T3 catalogs, command-line versions and a fresh composer selection across hosts.

## Repository rename and rollback

Update an existing checkout's `origin` to `https://github.com/Artic0din/devkit.git`; keep its local directory in place.
For a reusable workflow caller, change `Artic0din/agent-scripts/.github/workflows/` to `Artic0din/devkit/.github/workflows/` explicitly.
GitHub does not redirect reusable workflow calls after a rename.
Keep the reviewed commit SHA and the matching `agent-scripts-ref` value unchanged for an address-only migration.
The input name and `.agent-scripts` checkout directory are retained for existing callers.
New callers follow the adoption steps in [GitHub intake](docs/github-intake.md).

The 2026-10-10 inventory inspected 208 workflow files on the default branches of all 46 active repositories visible under `Artic0din` and `Plaintext-Lab`, including forks.
It found the old address in this repository's reusable triage workflow and in `Artic0din/unshackled`'s triage caller.
Track downstream adoption and machine validation in [#46](https://github.com/Artic0din/devkit/issues/46).

To roll back a caller update, restore its previous reviewed SHA and matching `agent-scripts-ref`, keeping the current `Artic0din/devkit` address.
To roll back local remote configuration, restore the recorded previous URL; GitHub currently redirects the old Git URL.
Do not recreate a repository at `Artic0din/agent-scripts`, because that would remove the redirect.
A GitHub name rollback must be coordinated with every migrated caller; reverting code alone does not restore the repository name.

## Syncing downstream

Treat this repo as canonical for shared rules and portable helpers. When syncing a downstream repo: pull here first; ensure it starts with the pointer-style `AGENTS.MD`; preserve its local rules; copy helper changes in both directions only when a helper is meant to stay byte-identical; keep scripts dependency-free. For submodules, repeat the pointer check inside each subrepo, push, then bump the submodule SHAs in the parent.
